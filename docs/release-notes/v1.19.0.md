## Pixel VR Player v1.19.0: Move / Copy anywhere, the vault on the SD card, safer vault

> [!IMPORTANT]
> **If you use the vault, please update.** Before this version, uninstalling deleted the written-down
> combination and suggested a command that deletes the vault key, which leaves encrypted files that can never
> be opened again. This version keeps both, warns you, and can decrypt the vault for you when you uninstall.

### 📁 Move and Copy
- **File Actions › Move / Copy:** open the folder you want in the normal file browser and press **Move here** /
  **Copy here** (or **Cancel**). A bar at the top shows what you are moving. Any folder works: Home, the SD card,
  new folders made with **+ Folder**, and the vault while it is unlocked.
- **Matching files travel along:** a video's scripts and subtitles (`Movie.funscript`, `Movie.en.srt`, ...) are
  moved or copied with it.
- **Runs in the background** with progress at the bottom; the player keeps running, also for big moves to or
  from the SD card. A file is deleted only after its copy is complete and on disk.
- Moving a playing video, a file that is still downloading, or a folder into itself is refused with a reason.

### 🔐 Vault
- **Into and out of any vault folder:** files moved into the vault (also into subfolders) are encrypted right
  away; files and whole folders moved out are decrypted under their real names.
- **The vault on the SD card:** Settings › Vault & Privacy › **Vault Location** moves it to the card and back
  (click twice to confirm). The key and the combination stay on the headset, so the card alone can't be read.
  Without the card the vault shows "Insert the SD card with your vault"; pulling the card while the vault is
  unlocked locks it.
- **Thumbnails of vault files are encrypted** too, and stay on the headset.
- Encrypted files outside the vault (for example in a folder moved out by an older version) count as vault
  files everywhere: no resume positions, thumbnails or plugin access without your permission.
- Safety: a file encrypted with another key is refused instead of being turned into garbage, and the player
  never creates a new key while encrypted files exist.

### 🗑 Uninstalling with a vault
- The uninstaller tells you how many files are in the vault and, from a terminal, asks: **keep it encrypted**
  or **decrypt it into `~/PixelVR Vault`** first.
- A kept vault keeps the written-down combination (`PixelVRPlayer/logs/session.dat`), and the closing hint no
  longer suggests deleting the vault key.

### 💾 SD card and downloads
- **SD card removed** during a download: the download stops with that message, downloads queued to the card
  fail the same way (they are never sent somewhere else), and **Retry** starts them again once the card is back.
- **Download Folder › Other...** picks any folder with the same folder picker (not the vault).
- "Stored in" shows where each download really went; finished downloads are synced to disk first.
- The SD card is a root in the file browser: its path starts at "SD card" and ".." goes back home.

### 🐞 Fixes
- Removing a failed download no longer deletes an older complete file of the same name.
- Stopping a folder download no longer deletes a folder of the same name that was already there.
- A folder bookmark made from a file's menu no longer gets the file's name.
- Rename and Delete check that the file list did not change while the menu or keyboard was open.
