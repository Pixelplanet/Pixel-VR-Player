## Pixel VR Player v1.14.0 — new controls, button labels, smoother playback

### 🎮 New controls, set up in SteamOS
- Buttons are now assigned in SteamOS, like any other VR game: **SteamVR Settings › Controllers ›
  Manage Controller Bindings**. Remap anything there, including chords, long-press and double-press.
  The player follows whatever you choose.
- A new default layout for the Steam Frame controllers:

| Button | Does |
| --- | --- |
| Trigger | Select / drag |
| A | Play / OK |
| B | Back, one step at a time |
| Menu | Main menu (file browser and settings) |
| View | Show / hide the player controls |
| Y | Options (file actions, including Download) |
| X | Recenter |
| Bumpers | Previous / next tab in menus, previous / next track in music |
| D-pad | Moves through menus; volume and ±10 s while watching |
| Right stick | Scrub (left / right), screen distance (up / down) |
| Left stick | Skip 30 s, screen distance |
| Stick click | Show / hide button labels |
| Grip | Move the laser to that hand |

- **360/180 videos work with one controller:** the right stick tilts and zooms, the left stick scrubs.
- More actions with no default button, ready for chords: Mute, Stop, Bookmarks, Next / Previous
  Screen, Back / Forward 30 s, Lock Screens, Audio Track and 3D Format.
- **Settings › Controls & Input › Controller Buttons** lists every action with the button it is bound
  to right now, says when a controller is off, and warns if an essential button isn't bound.
- In-app button remapping is gone; SteamOS is the one place to change buttons. If you had changed
  buttons in the player before, a notice tells you once.

> [!NOTE]
> SteamOS shows OpenXR apps' button names as short internal names (e.g. `play-ok`, `main-menu`).
> That is a SteamVR limitation for every OpenXR app; the in-player labels below show the full names.

### 🏷 Floating button labels
- Labels float next to each controller button and say what it does right now: in menus, while
  watching, on web pages, in 360/180 and while typing. They follow your SteamVR bindings, so a
  remapped button shows its new job.
- Toggle them with a stick click, or in **Settings › Controls & Input › Button Labels** (on by default).
- Cards are fixed to the controller with thin lines ending in a ring around each button; lines never
  run through the controller, and cards fade when held close to your eyes. Over 3D and 360/180 video
  the cards turn nearly opaque so they are easier to read.

### ▶️ Playback
- **Exact scrubbing:** after scrubbing, playback continues exactly where you let go instead of jumping
  back to the previous keyframe.
- **Smoother at high resolution:** if you raise the render resolution in SteamVR, the player now lowers
  it automatically while something heavy plays (like 8K video) and raises it again when there is room.
  It never goes below the panel's native 2160 × 2160.
- **Much lighter 360/180 rendering:** 8K 60 fps 180° video now needs only a few milliseconds of GPU
  time per frame.
- The stats overlay shows the real render size and GPU time per part.

### 🕹 Controllers
- Controller models stay visible in front of screens and menus (they used to disappear behind a
  playing screen), and are on by default for new installs.

### ⚙️ Settings
- Default screen distance is now 4 m (closest 2 m), so a new screen never covers the menus and several
  screens have room.
